# T-818 dynamic demand-depth proof calibration

The public compiler proof in both rule-runtime tiers compounded a possible dynamic result across every potential Compute or aggregate cell. The graph scheduler refuses a new demand when its active chain already exceeds `maxDependencyDepth` (`graph.ts` and `FormRuleGraph.cs`). Completed cells can be read without entering that active chain, but expression-valued `missing` and `missing_some` use demanded values only to test presence and return key names; a computed value used to build a key travels through a static `var` reference, which the compiler depth-checks. Those two paths limit a successful result-carrying chain to `maxDependencyDepth + 1` cells. Total work may still visit independent cells across the full graph. This slice caps only the result-transfer exponent by the smaller of that chain length and the potential-cell inventory; it leaves the total-work cell multiplier and the runtime step budget intact. Under default limits, the TypeScript diagnostic Row `missing(var rowKeys)` proof changes from 22,395 result digits and 22,411 work digits to 301 and 316 digits. This is still a conservative proof, not a calibrated admission ceiling.

The public TypeScript compiler test failed red because three possible Row cells yielded `35389589809091836394000` result bytes instead of the two-cell result `1179652993636394000` under a demand depth of one. The corresponding .NET public compiler test failed for the same equality. The minimum proof changes made both focused tests green. Mutation review then exposed a valid zero-depth boundary that the first test missed. An initial `missing(var rowKeys)` zero-depth test could not compile because its static reference exceeded that depth; it was corrected to an expression-valued missing key with no static dependency. The first follow-up's equality-only assertion did not kill the zero-depth undercount. Comparing its one-cell result with the empty-program result did; that test passes on the original code and kills the undercount mutant in both tiers. The affected TypeScript package passed 352 tests, type checking, lint and build; the affected .NET RuleEngine test project passed 305 tests. No refactor was needed.

This closes one overinflated proof dimension and verifies its depth-one and zero-depth boundaries at public compiler seams. It does not establish a shared static admission ceiling, fail-closed compile or graph refusal, proof validity for every admitted expression, or released consumer behavior.
