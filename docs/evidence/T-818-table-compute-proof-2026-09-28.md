# T-818 Table Compute aggregate result proof

The public compiler proof understated a resolved result when a Table Compute wrote an aggregate cell and a downstream expression copied that cell repeatedly. A Table Compute is value carrying: the graph evaluates its expression into the addressed aggregate cell. The proof previously used only the generic aggregate-fold bound, which did not include the Table Compute expression's bound. Both tiers now propagate the Table Compute bound to its aggregate cell during fixed-point derivation and use the larger of that bound and the fold bound at an `agg` reference. The mapping retains the maximum for duplicate Table targets, so the proof remains conservative when admission allows a later rule to replace an earlier target.

The public TypeScript test was written first and failed at its result-bound assertion: `maximumResultBytes` was 491,840 while the resolved serialized value occupied 800,002 bytes. The corresponding .NET public test also failed at the bound assertion after producing a resolved value. The minimum production changes made the focused tests green. Mutation review exposed a duplicate-target boundary; public tests in both tiers now cover a small first Table Compute replaced by a large second one. The TypeScript test's first run had an invalid JSON string-expression fixture, which was corrected before treating it as behavioral evidence. The .NET duplicate test was green on the original production code and later killed the selected duplicate-bound mutant. No refactor was needed.
