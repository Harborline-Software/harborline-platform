# T-818 dynamic missing presence proof

Both rule-runtime compilers classified expression-valued `missing` and `missing_some` keys as dynamic reads. Their graph proof then repeatedly compounded the maximum result for every potentially demanded cell. The interpreters use each dynamically resolved value only to test presence and return the key name when absent (`HarborlineJsonLogic.EvalMissing`/`EvalMissingSome` and the corresponding TypeScript evaluator). The compiler's static `var` references already propagate value-carrying results through its fixed point. A dynamic missing lookup can cause another cell to run, but it cannot copy that cell's value into its own result. Both proofs now retain the fixed-point maximum as the result bound and charge dynamic lookups and possible demands in the work bound.

The public TypeScript Row compiler test was changed first to require equal maximum result bytes at one and two admitted graph cells while requiring greater maximum work at two cells. It failed red at `1,179,652,502,291,836,394` versus `39,321,750,076,394` bytes, then passed after the minimum TypeScript proof change. The equivalent .NET public compiler test failed red with the same values and passed after the .NET change. Existing assertions that intentionally pinned the older overestimate were updated or removed; six public cross-tier calibration cases were repinned to matching values. The affected TypeScript package passed 352 tests, type checking, lint and build; the .NET RuleEngine test project passed 305. Shared outcome conformance passed 80 cases with byte-identical canonical values. These checks cover the affected projects and corpus, not every released consumer.

Repository-pinned StrykerJS 10.0.0 used default `perTest` coverage, the compiler admission and proof-parity test files, and `--mutate "src/core-work.ts:204-204,src/core-work.ts:242-258"`. Eleven of 12 selected mutants were killed. The survivor makes the work-only dynamic-read condition always true; for programs with no dynamic read this only raises the conservative work estimate and does not understate an admitted result. At default limits, the diagnostic one-rule dynamic Row proof changes from 301 result digits and 316 work digits to 10 and 25 digits. One through 64 dynamic Field Compute cells now have 10 result digits and 18 through 22 work digits. These are proof magnitudes, not measured runtime operations, and the structural work units are still not interchangeable with the 250,000-step runtime budget. The removed recurrence has no equivalent surviving insertion mutant; the public test's observed red failure against the previous proof is the direct check for that behavior. A shared static admission ceiling, compile/graph refusal, whole-program bound validity, released consumer enforcement and CK7 closure remain open.
