# T-818 dynamic cell inventory in the rule-runtime proof

The public seam is `compile(...).workProof` in TypeScript and `RuleCompiler.Compile(...).WorkProof` in .NET. A dynamic rule with one Field Compute has one possible demand cell regardless of unused `maxGraphNodes` capacity. A Row Compute can expand across admitted rows, and an aggregate reference adds a distinct demand cell. The prior derivations applied the entire configured graph cap to every dynamic rule, making one valid rule's default proof 22,395 decimal digits. The new derivations count potential Compute and aggregate cells and cap that count by `maxGraphNodes`; Row Compute remains conservatively bounded by the graph cap. This is a proof-calibration slice, not the T-818 admission ceiling or enforcement decision.

The first TypeScript compiler test failed red because the default-capacity proof differed from the same one-cell rule at `maxGraphNodes=1`; after the minimum derivation change, the focused test passed. The corresponding .NET test first failed red with `Assert.Equal()` showing one-cell `MaximumResultBytes` expected `39321766454000` and a much larger default-capacity result, then passed after the .NET change. Public tests added after survivor review check that adding a real Compute or aggregate cell increases the result bound, that a Validate rule is not counted as an additional Compute cell, that work covers producing the result, and that Row Compute proof growth tracks row-cell capacity. The affected TypeScript package passed 344/344 tests plus type checking and lint. The affected .NET RuleEngine test project passed 297/297 tests. No refactor was needed.
