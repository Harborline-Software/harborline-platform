# Harborline Foundation Assistance

Owns the platform-neutral Assistance definition contract: canonical JSON, phase-aware command and safety-floor admission, and provider-neutral pack export under the shared builder-definitions `DefinitionKind.Pilot` namespace. It owns no command catalogue, definition store, runtime proposal evaluation, or model execution.

At Author, Publish and Install, the injected `ICommandCatalogueRegistry` supplies each command's exporting package, export status, tier floor, argument schema and permitted recipients. A binding may only narrow these entries; binding-wide recipients must be permitted by every referenced command. T-612 supplies the released authority-artifact adapter; this foundation package has no blocks dependency.

`AssistanceArgsSchemaNarrowing` provides a sufficient inclusion proof for required names, enum subsets, numeric/string/array bounds, properties, items and additionalProperties. All numeric leaves must be exactly representable as decimal; rounded, out-of-range or extreme-exponent conversions refuse before equality shortcuts. Newly added subschemas are checked against an unconstrained schema; unmodeled additions refuse. Deep equality and enum searches share the comparison budget, including nested values. Type and pattern changes refuse; unsupported keywords must remain structurally equal. Opaque applicators require equality of their containing schema, and a reference anywhere requires equality of the entire schema, because sibling target changes can reverse inclusion under negation. Duplicate object names anywhere refuse. Missing baseline constraints refuse. The same checker protects previous versions. Schemas are bounded to 65536 JSON characters each, 64 JSON nesting levels, 4096 shape nodes across both schemas, 32 nested comparisons and 4096 comparison steps; exceeding a bound refuses. This is intentionally conservative, not a general JSON Schema inclusion solver.

Undefined command classification tiers refuse as `definition.body_invalid` for typed and JSON admission. Recipient refusals retain command/index order and are deduplicated by recipient index using a set, without a recipient-count limit.

## Runtime wire shapes (T-610)

`AssistanceDelegationJson.Deserialize<T>` and `SerializeCanonical<T>` validate `AssistanceProposalEnvelope`, `AssistanceDelegationRecord`, `AssistanceDisposition` and `AssistanceStandingApproval`. Unknown, duplicate, missing and invalid members refuse with `JsonException`. Use these codecs at the wire boundary, not an unconfigured `JsonSerializer`.

- A proposal remains `{schema: "pilot.proposal/3", surface, command, args}`. Canonical UTF-8 sorts object names ordinally at every depth (RFC 8785 section 3.2.3), preserves array order and has no trailing newline. `AssistanceProposalDigest.Compute` returns `sha256:` followed by lowercase hex SHA-256.
- Delegation is `{subject, actor, disposition}`. Its actor has exactly `binding_key`, `binding_version`, `provider_id`, `model_version`, `proposal_digest`; it has no proposal-content or context member. A hand-performed act has `actor: null`.
- A disposition is `{kind: approve|dismiss|clarify|reject}` or `{kind: standing, approval_id, approver, scope, expires_at}`. Dismiss is recorded, not an absent decision.
- Standing approval is `{id, approver, binding_key, scope: {surface, commands[]}, schedule, expires_at, revoked_at}`. Approver and a nonempty command scope are required. UTC instants use `Z` or `+00:00` and up to seven fractional digits; expiry is required and revocation may be null. Schedule is an RRULE string or null, preserved without expansion or recurrence-grammar admission.

These are data shapes, never dispatch authority, audit writers or act-time approval coverage (T-613). No dispatch receipt is serialized or minted here. `AssistanceDefinition` and its pack exporter carry none of these runtime shapes or user grants. The shared `conformance/hlp.copilot/delegation-cases.json` pins wire values, canonical bytes and independent `shasum -a 256` digest literals in both lanes. Its digest corpus covers integer arguments; exhaustive non-integer RFC 8785 number agreement remains the slice record's follow-up.
